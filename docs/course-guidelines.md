## 2. 課程結構

### 科目、單元、順序

- 每科 15–20 堂，依「單元」分組。單元名稱與順序寫在 `src/data/units.ts`。
- 課程排序只靠 frontmatter 的 `order`（同科內不可重複）。依 `order` 排序後，單元順序不能倒退。
- 對象是高中到大學一年級。
- 完整大綱在 `docs/syllabus.md`。照確認後的大綱撰寫；需要調整大綱時，先提出來，確認後再改，並同步更新 `docs/syllabus.md`。

### 網址與檔名

- 檔名就是 slug，也就是網址：`src/content/lessons/<科目>/<slug>.mdx` → `/<科目>/<slug>/`。
- slug 用小寫英文單字加連字號，**不含編號**（`quadratic-equations`，不要 `01-quadratic`）。
- 課程 slug 全站唯一（先備課程可以跨科目引用）。
- 改名或拆分課程時，在 `astro.config.mjs` 的 `redirects` 加上舊網址的轉址；拆分的課程，舊網址轉到第一堂。

### frontmatter

```yaml
---
subject: algebra
unit: polynomials
order: 6
title: 一元二次方程式
summary: 用因式分解、配方法和公式解來解二次方程式，並用判別式判斷根的情況。
prerequisites: [factoring]
formulas: [quadratic-formula]
theorems: [vieta]
---
```

- `summary`：一句話摘要，顯示在科目頁。可以含 `$...$` 數學式。
- `prerequisites`：只列**直接**需要的課程。同科目的先備課程必須排在這課之前；跨科目可以（例如微積分引用代數）。不可形成循環。
- 跨科目真的用到的課程也要列進去，不要只列同科目的。例如〈正弦與餘弦函數的圖形〉用到函數的定義域、值域和圖形平移，就列代數的 `functions-domain-range`、`function-transformations`。
- `formulas`、`theorems`：這課用到的公式頁、定理頁 slug，顯示在課程頁底部「相關公式與定理」。
- 不要再用舊的 `example`／`solution` 欄位，例題一律寫在內文。
- 以上規則由 `src/lib/lessons.ts` 在建置時檢查，違反時建置失敗。

## 3. 每堂課的固定格式

```markdown
## 學習目標
（2–3 點，用「學完這課，你能……」的句型）

## 概念說明
（從學生已經會的東西出發，先講直觀，再講正式定義或方法。需要的話分成幾個 ### 小節。）

## 例題
（2–3 題，由淺到深。最後一題最好是應用題或綜合題。每題用 ### 例題 n 標題，解答放在 <Solution>。）

## 常見錯誤
（2–3 個，每個寫出「錯誤寫法、為什麼錯、正確寫法」。）

## 練習題
（3–5 題，附答案，答案預設收起，用 <Solution answer>。至少一題需要用到先備課程的內容，並在題目後註明，例如「（需要上一課的十字交乘）」。）
```

### 例題

```mdx
### 例題 1

題目……

<Solution>

解答……（前後要空一行，MDX 才會把內容當 Markdown 和數學式處理）

</Solution>
```

### 常見錯誤

```markdown
**錯誤 1：一句話描述錯誤。**

- 錯誤寫法：……
- 為什麼錯：……（最好附一個代數字檢查的反例）
- 正確寫法：……
```

### 練習題

```mdx
**1.** 題目……

<Solution answer>

答案與簡要過程……

</Solution>
```

## 4. 內容與寫作要求

### 推理要完整

- 每個推導和解題步驟都要有理由，**不可以用「顯然」「易知」跳過**。
- 先講「為什麼」再講「怎麼做」。公式要說明來源（推導或直觀理由），不要只丟公式。
- 結論需要兩個方向時要兩邊都說明。例如求值域要說明「不會超出」和「每個值都取得到」。
- 用到尚未教過的概念時，先直觀使用並註明之後在哪一課正式介紹（例如二次函數先用 $f(x)$，〈函數的概念〉再正式定義）。

### 數字與答案

- 例題和練習題的數字要挑得剛好能算出整齊的答案（除非題目本身就是估算）。
- 需要估算時（例如 $\log2\approx0.3010$），題目要給近似值，並附合理性檢查（答案應該落在哪兩個數之間）。
- 解答最後盡量附驗算（代回原式、用另一種方法再算一次）。

### 長度與範圍

- 每堂課約學生 15–25 分鐘能讀完並做完例題的份量。
- 課程太長時，把次要主題移出概念說明，改放在常見錯誤或練習題（例如除以 $ax-b$ 的綜合除法）。
- **延伸的定理不要硬塞進課程**：只把該定理加進 `theorems`，讓課程頁底部連到定理頁即可（例如〈一元二次方程式〉不講根與係數關係，只連到〈根與係數關係〉）。
- 適合當例題的經典證明可以放進例題（例如 $\sqrt2$ 是無理數）。

### 新名詞要解釋

- 新名詞第一次出現時，要說明它是什麼、在圖上或式子裡對應到哪裡，不能只丟名詞（例如〈和差化積與積化和差〉的「包絡線」：先說明它是把快速振動的波從外面包住的曲線，再用不等式說明為什麼波永遠夾在它中間）。

### 公式與定理

- 課程用到重要的公式或定理，但公式／定理列表裡沒有時，**不要自己新增**。在該批結束時列出來，由使用者決定要不要加。
- 使用者決定新增時，公式頁放 `src/content/formulas/<科目>/`，定理頁放 `src/content/theorems/<科目>/`，格式照現有頁面：
  - 公式頁：`## 符號說明`、`## 使用時機`、`## 例題`（2 題，`<details class="example-solution">`）、`## 推導`。
  - 定理頁：`## 白話解釋`、`## 使用時機`、`## 例題`、`## 證明`，frontmatter 的 `proofType` 填 `full` 或 `sketch`。
- 新增後依教學順序調整同列表其他項目的 `order`，並把它加到相關課程的 `formulas`／`theorems`。
- 使用者也可能事先指定要新增哪些頁（例如三角函數的〈負角、補角與餘角關係〉、〈積化和差與和差化積〉、〈海龍公式〉、〈棣美弗定理〉）。這時寫到用到它的課程時再加，並讓所有用到它的課程（包括先前已寫好的）底部都連到它。

## 6. 數學符號寫法

KaTeX 以 `strict: 'error'` 執行，任何警告都會讓建置失敗。

- 行內 `$...$`，獨立一行 `$$...$$`（前後各一行）。
- **數學式裡的中文必須包在 `\text{}` 裡**，例如 `$\text{對邊}$`、`\text{（兩邊同加 }3\text{）}`。
- 數學式裡不能用 ①② 等特殊符號，改用 `(1)`、`(2)`。
- 行內分數若需要看得清楚，用 `\dfrac`；組合數用 `\binom{n}{k}`（行內用 `\dbinom`）。
- 多步驟推導用 `\begin{aligned} ... \end{aligned}`，理由用 `&& \text{（理由）}` 寫在右邊。
- 區間：`[a,b]`、`(a,b)`、`[a,b)`、`(-\infty,b)`，無限大那端永遠用圓括號。
- 對數寫 `\log_a b`，常用對數寫 `\log x`。
- 數字代入時負數加括號：`(-2)^2`，不要寫 `-2^2`。
- frontmatter（YAML）裡的數學式不要用雙引號包，雙引號會把 `\frac`、`\theta` 等反斜線吃掉；用不加引號或單引號。

### 版面：不要擠在一起、不要太寬

- **連續幾行文字或清單項目中，不要用 `\dfrac` 這類高的行內分數**，上下兩行的分數會疊在一起。改用文字敘述（「$\sin\theta$ 是 $y$ 除以正數 $r$」），或把式子獨立成一行。
- **手機寬度的內容區只有約 320px。** 一行並排好幾個式子時拆成多行（`gathered`、或 `aligned` 在 `=` 處換行）；寬度超過約 400px 的式子一定要拆。略寬一點的式子會在自己的區塊內左右捲動（網站的設計），可以接受。
- 表格欄位不要多：寬的表格改成直的（每列一項，例如象限、參考角、正負號各一欄），或拆成兩張；一長排數值的 `array` 拆成兩段。

### MDX 注意事項

- 內文的 `{`、`}` 會被當成 JavaScript，數學式外不要用大括號（改用「」）。
- 數學式外不要寫 `<`，會被當成 HTML 標籤；不等式一律寫在 `$...$` 裡。
- 元件的內容（`<Solution>` 等）前後要空一行。
- 元件可以放在清單項目裡，但要縮排對齊清單內容並前後空行。

## 7. 元件

課程頁可以直接使用以下元件（定義在 `src/components/`）：

| 元件 | 用途 |
|---|---|
| `<Solution>` | 例題解答，按鈕「看解答」 |
| `<Solution answer>` | 練習題答案，按鈕「看答案」 |
| `<Graph name="科目/名稱" />` | 互動圖形；加 `proof` 變成逐步證明 |
| `<ProofStep n={1}>` | 搭配 `<Graph proof>` 的證明步驟段落 |
| `<Derivation rows={[...]} />` | 推導逐行顯示，附上一步／下一步按鈕 |
| `<LongDivision dividend={[...]} divisor={[...]} />` | 長除法直式 |
| `<SyntheticDivision dividend={[...]} root={a} />` | 綜合除法表格 |

- `<Graph>` 可以放在 `<Solution>` 裡。答案展開時圖才會畫出來；`pnpm test:e2e` 會先展開解答再檢查裡面的圖。

### 推導要能逐步看

- 重要的推導（例如配方法、公式解）用 `<Derivation>` 逐行顯示，每一行附理由，操作方式和證明圖形一樣（上一步／下一步／重來）：

  ```mdx
  <Derivation rows={[
    [String.raw`x^2+6x+2`, '=0', '原方程式'],
    [String.raw`x^2+6x`, '=-2', '常數項移到右邊'],
    [String.raw`x^2+6x+9`, '=-2+9', String.raw`兩邊同加 $\left(\frac{6}{2}\right)^2=9$`],
  ]} />
  ```

  有反斜線的字串一律用 `String.raw`。

- **推導需要圖時，圖要是推導的一部分**：用 `<Graph name="…" proof />` 加上 `<ProofStep n={…}>` 段落，每一步同時更新圖（顯示、強調、動畫）和這一步的式子，不要分成「幾個 `<Derivation>` 區塊＋另一張圖」。步驟段落裡放完整的式子與理由，點段落會跳到那一步（範例：〈和角與差角公式〉推導 $\cos(\alpha-\beta)$、〈畢氏定理〉定理頁）。一頁只能有一張 `proof` 圖。

### 除法一定要顯示過程

- 例題或練習題的解答只要用到長除法或綜合除法，**一定要顯示直式或表格**，不能只寫結果。
- **例題**加 `steps` 做成逐步示範：`<SyntheticDivision dividend={[2, -3, -11, 6]} root={-2} steps />`。
- **練習題答案**顯示完成的表格（不加 `steps`）。
- 係數由高次到低次，缺項補 `0`。係數必須是整數，建置時會檢查 $f=gq+r$。
- 長除法另有獨立的逐步示範頁 `/algebra/long-division/`，在〈多項式的運算與除法〉有連結。

## 8. 互動圖形

- 圖形和示意圖的數量**不限**，有助於理解的地方就加（例如〈廣義角與象限〉的概念圖加上例題、練習題的示意圖共 6 張）。但**不要為了加圖而加圖**：每張圖都要說明一件文字不容易說清楚的事。能沿用現有圖形就沿用（`src/graphs/` 下）。
- **一張圖只放本課的內容**，下一課的主題不要先畫出來（例如〈單位圓與弧度〉只放單位圓，正弦、餘弦的曲線留到〈正弦與餘弦函數的圖形〉）。
- **不要重複的圖解**：公式頁或定理頁已經有的圖解，課程裡不必再放一次（例如疊放的直角三角形證明 $\sin(\alpha+\beta)$ 只留在〈和角公式〉公式頁）；和推導主線無關的圖拿掉。不再使用的圖形檔要刪除。
- 新圖形照現有格式寫在 `src/graphs/<科目>/<名稱>.ts`，型別見 `src/graphs/types.ts`；只能 `import type` jsxgraph。
- `description` 要完整說明圖形內容與操作方式（給螢幕閱讀器和無法載入時使用）。
- 顏色只用 `ctx.color` 的色彩變數，深色模式才會正確。

### 例題與練習題的圖

- **函數的例題**（例如振幅與相位、疊合），解答裡畫出實際的函數圖形，標出關鍵點（最高點、最低點、起點、五個關鍵點、區間端點）；需要比較時加上對照曲線（例如平移前的圖形、$y=\cos x$）。
- **幾何或角度的題目**（終邊上的點、三角形、測量），畫出示意圖，標出角、邊和已知的長度。
- 例題的題目若需要圖才看得懂（例如測量題），圖放在題目下方；其他的圖放在解答裡。練習題的圖一律放在答案裡，不要洩漏答案。
- 這類固定的圖用共用的工廠函式產生，每題一個小檔案：`src/graphs/terminal-side.ts`（終邊上的點、$x$、$y$、$r$）、`src/graphs/sinusoid-plot.ts`（函數圖形、標記點、對照曲線）。工廠函式放在 `src/graphs/` 根目錄，不會被當成圖形載入。

### 操作要求

- **拖動要自由**：滑桿和可拖動的點精度 0.1，不要用 0.5 這種大格子。
- **沿著圓或曲線拖動的點要平順**：角度連續變化，不要四捨五入到整數度或 0.1 的格子；只在接近特殊角（$30^\circ$、$45^\circ$ 的倍數）$1.5^\circ$ 以內時吸附。
- 自由拖動時，特殊情形（平行、重合、重根）很難剛好對到，加**吸附**：接近時自動對齊（例如角度差 2° 內變平行、兩根相距 0.2 內重合）。
- 重要的點跑出畫面時要提示（例如交點在畫面外時，邊緣顯示指向它的箭頭，下方文字說明並給出坐標）。
- 預設狀態要能看出效果：變換後的圖形不要和原圖完全重疊，兩個點不要疊在一起。
- 讀數裡的數字用簡潔格式（`1`、`-2.5`，不要 `1.00`）；係數 ±1 省略；負數平方加括號；相同的因式寫成次方 $(x-1)^2$。
- 一張圖只講一件事。內容太多時拆成兩張（例如「平移」用 h、k 滑桿，「伸縮與鏡射」另一張用動畫）。

### 線條與標籤

- 多條曲線用**顏色**區分。虛線只用在「原圖、變換前、對照用」的曲線和輔助線；其他曲線（例如和疊合結果比較的 $y=\cos x$）用實線，**不要用點線**。
- **標籤不能壓到線或被切掉**，手機寬度特別要看：標籤從線的外側錨定（例如 $x$ 軸下方的標籤 `anchorY: 'top'`）；擠的時候改用短標籤（$A$、$B$、$A'$），坐標寫在步驟文字或讀數裡；點已經標了坐標時，坐標軸可以不放刻度數字。
- 橫向很長的函數圖（例如 $0$ 到 $5\pi$），寬高比最多 $2$，讓 $y$ 方向拉長（`keepAspectRatio` 是 `false`），不要在手機上變成一條扁扁的帶子。
- 讀數（`ctx.readout`）只會轉換數學式，不要用 Markdown 粗體。用樣板字串組 LaTeX 時，`\sin`、`\cos` 等指令後面接變數要留空格（`${name} x`），否則會變成未定義的 `\sinx`。

### 按鈕與動畫

- 有多組選擇時，用 `ctx.button(label, onClick, { row: '函數', pressed: () => ... })` 做成**分列的選擇按鈕**，每列有標籤，選中的按鈕會填滿顏色。選擇列放在**圖形上方**。
- 動畫用「▶ 播放」「◀ 倒轉」兩個按鈕放在圖形下方，從目前進度繼續播放；選擇變換時只顯示起點，按播放才動。
- 動畫的插值要選讓過程好看的參數（例如鏡射時讓水平縮放倍率從 1 變到 −1，圖形會「翻頁」，不要讓 $b$ 經過 0 而衝到無限遠）。

### 檢查

- `pnpm test:e2e` 會開啟每個有 `<Graph>` 的頁面，檢查圖形有畫出來、沒有錯誤、沒有水平捲動。
- 新圖形要實際在瀏覽器拖動、按按鈕，桌機與手機寬度、淺色與深色模式都看過。逐步證明圖要每一步都點過，動畫步驟要等播完再看。

## 9. 驗算

- 每一批寫完後，把所有例題、練習題的答案**重新獨立算一次**，連概念說明中的計算、常見錯誤裡錯誤與正確的結果一起驗。
- 能用程式驗算的用 SymPy：腳本放在 `scripts/verify/<科目>_batch<n>.py`（不加入網站），格式照 `scripts/verify/algebra_batch*.py`。
- SymPy 裝在 `scripts/verify/.venv`（已 gitignore）：
  - 建立：`python3 -m venv scripts/verify/.venv && scripts/verify/.venv/bin/pip install sympy`
  - 執行：`scripts/verify/.venv/bin/python scripts/verify/<科目>_batch<n>.py`
- 證明題驗算歸納步驟的代數恆等式與起始步驟，並對很多個 $n$ 實際檢查。
- 估算題用容許誤差比對。
- SymPy 的已知問題（三角函數課程遇過）：
  - `expand_trig` 遇到 $\sin(880\pi t)$ 這種很大的倍數會跑非常久，改成在幾個點代數值比對。
  - `solveset` 解三角方程式不可靠（可能漏解或直接出錯）。改成：把宣稱的每個解代回去精確檢查，再在 $[0,2\pi)$ 上用很密的數值掃描確認沒有漏解（`trig_batch4.py` 的 `roots_in_0_2pi`）。
  - `acos`、`atan` 的和常常化簡不出來，改成驗算它們的 $\cos$ 或 $\tan$，再說明角的範圍。
  - 驗算腳本用 `python -u` 執行；可能跑很久的腳本放到背景執行，避免逾時看不到輸出。
- 在回報中列出驗算結果（通過幾項）。

## 10. 工作流程

- 每次寫 **4 堂課為一批**（剩下不足 4 堂時可以做成短批次），寫完一批就停下來讓使用者檢查。科目順序：代數 → 三角函數 → 微積分 → 線性代數。
- 每批結束時：
  1. `pnpm build` 通過（也會檢查 KaTeX 錯誤、先備課程、slug）。
  2. `pnpm test:e2e` 通過。
  3. 檢查 `dist/` 裡所有站內連結都有效。
  4. SymPy 驗算全部通過。
  5. 瀏覽器實際看過新頁面與新圖形（桌機、手機、深色模式），並在手機寬度（375px）檢查有沒有太寬的式子或表格（見第 6 節）。
  6. 做一次 git commit。
- 回報內容：
  - 改了哪些檔案。
  - 驗算結果。
  - 用到但列表裡沒有的公式或定理（不要自己加）。
  - 只靠直觀、沒有完整證明的地方。
  - 需要使用者決定的事。
- 套件管理一律用 pnpm。開發伺服器用 `astro dev --background`。使用者在 `http://localhost:4321/` 檢查頁面，回饋會直接指出網址和小節。
- 課程寫完、使用者看過之後，修改通常是：拿掉多餘的圖、把推導和圖結合、在解答加圖、解釋新名詞、改線條樣式。寫新課程時先照本文件做好，可以減少來回。
- 現有課程改寫成新格式時，原本的內容（包括舊的 frontmatter 例題）都要保留下來，搬進新結構；拆分的內容依 `docs/syllabus.md` 的「現有內容的去向」處理。
- 科目全部完成後，更新 `src/data/subjects.ts` 的科目簡介，讓它反映所有單元；並在 `features/FEATURE-more-lessons.md` 的「進度」標記完成。
- 大綱的決定（例如三角函數的 sec、csc、cot 在〈廣義角與象限〉定義）記在 `docs/syllabus.md` 的「待確認事項」，使用者確認後改成「已確認」。
